* Versions

** <2026-08-29 Sat> *2.4.0*

Move images to another directory.

*** New Features

- *Move to directory (v)* -- Added `dired-image-thumbnail-move` (bound to =v=, also in the transient menu under Other). It moves the marked images -- or, when nothing is marked, the image at point -- into a directory chosen with `read-directory-name', defaulting to the source directory. The target directory is created if needed (confirming first), existing destinations are overwritten only after confirmation (both controlled by `dired-image-thumbnail-auto-accept'), and the Dired buffer and thumbnail display are refreshed afterwards.

** <2026-08-29 Sat> *2.3.1*

Deletion now respects the auto-display setting.

*** Bug Fixes

- *Deletion forced a display* -- `C-d` (`dired-image-thumbnail-delete-and-next` and `dired-image-thumbnail-delete-image-and-next`) always displayed the next image, ignoring `dired-image-thumbnail-auto-display-on-navigate`. With auto-display off, deleting now only moves to the next thumbnail, matching the behaviour of navigation and marking.

** <2026-08-29 Sat> *2.3.0*

Toggle for automatic image display while navigating.

*** New Features

- *Auto-display toggle (a)* -- Added `dired-image-thumbnail-toggle-auto-display` (bound to =a=, also in the transient Display menu). It toggles `dired-image-thumbnail-auto-display-on-navigate`, so you can step through or mark thumbnails without paying the cost of decoding each image -- useful when marking many files for a batch operation such as rotation.
- *Marking overhead follows the toggle* -- Turn the toggle off and image-dired's `image-dired-marking-shows-next` is set buffer-locally to nil, so marking/unmarking/flagging advances to the next thumbnail *without* displaying it. Previously that display was driven by image-dired directly and ignored this package's auto-display setting, so disabling auto-display alone did not remove the marking overhead. Set on buffer init and whenever the toggle is used.

** <2026-08-29 Sat> *2.2.8*

Prominent, customisable highlight for the current thumbnail.

*** New Features

- *Current thumbnail highlight* -- The selected thumbnail is now outlined with the new customisable face =dired-image-thumbnail-current-thumbnail=, so the selection is clearly visible regardless of theme (previous indication depended on the theme and could be a thin 1px border). Defaults to a thick box -- dark orange on light backgrounds, yellow on dark. Customise the face to change colour/width, or set =dired-image-thumbnail-highlight-current-thumbnail= to =nil= to disable. The highlight follows point via a buffer-local =post-command-hook= and is re-applied after each refresh.
- *Matching cursor colour* -- The cursor in the thumbnail buffer is now recoloured to match the highlight, making it easier to spot. The colour is derived from the =dired-image-thumbnail-current-thumbnail= face's :box attribute (so customising the face also changes the cursor) and applied buffer-locally via =face-remapping-alist=, so only thumbnail buffers are affected. Disable with =dired-image-thumbnail-highlight-cursor= =nil=.

** <2026-08-29 Sat> *2.2.7*

Fix square thumbnails on first run with an empty cache.

*** Bug Fixes

- *Square cropping skipped on first run* -- image-dired generates thumbnails asynchronously (jobs are queued and run by subprocesses after the command finishes), so on a first run with an empty cache the thumbnail file did not yet exist when the square crop ran, and the crop was silently skipped, leaving non-square thumbnails until a manual refresh. =dired-image-thumbnail-refresh= now splits thumbnail preparation into phases: queue all generations, wait for the queue to drain (keeping Emacs responsive), then crop, then insert.

** <2026-08-29 Sat> *2.2.6*

Square thumbnails by default and layout indication.

*** Changes

- *Square thumbnails enabled by default* -- `dired-image-thumbnail-square-thumbnails` now defaults to =t=. Set it to =nil= or press =#= for natural aspect-ratio thumbnails.
- *Thumbnail layout indicator* -- The header line now shows =[square]= when thumbnails are cropped to uniform squares, or =[natural]= when they keep their aspect ratio, next to the display-quality indicator. The transient state line already shows the Square state.

** <2026-08-29 Sat> *2.2.5*

Square thumbnail cropping for a tidier grid.

*** New Features

- *Square thumbnails (#)* -- Added `dired-image-thumbnail-square-thumbnails` defcustom (default =nil=) and toggle command =dired-image-thumbnail-toggle-square-thumbnails= (bound to =#=). When enabled, each thumbnail is scaled to fill and center-cropped to a uniform square of =image-dired-thumb-size= pixels so all thumbnails have the same dimensions and the grid lines up neatly. Requires ImageMagick (=mogrify= or =magick=). Existing thumbnails are cropped on the next refresh; use =G= (hard refresh) to regenerate from scratch. Also available in the transient menu's Display section, and shown in the transient state line.
- *Progress bar during thumbnail generation* -- =dired-image-thumbnail-refresh= now shows a progress reporter in the minibuffer when thumbnails need to be created or cropped, so you can see how far along the regeneration is. The progress bar only appears when there is actual work to do (not on refreshes where all thumbnails already exist). Creation and cropping are counted as separate work items and an explicit running counter is passed to =progress-reporter-update=, which fixes a =wrong-type-argument= crash when the value overflowed =max-value= (Emacs 30 passes nil through to =progress-reporter-do-update= once the reporter's value reaches its maximum).

*** Bug Fixes

- *Nil image-dired geometry variables* -- =image-dired-thumb-size=, =image-dired-thumb-relief=, =image-dired-thumb-margin=, and =image-dired-thumbs-per-row= can be nil if they were bound to nil before =image-dired= loads (Emacs's defcustom does not repair a non-void nil). This signaled =Wrong type argument: number-or-marker-p, nil= when pressing =#= and on first opening after clearing the thumbnail cache, because image-dired's own line-up functions use these variables in arithmetic unguarded (e.g. =(* 2 image-dired-thumb-relief)= in =image-dired-line-up-dynamic=). =dired-image-thumbnail-refresh= now repairs all four buffer-locally (thumb-size via the =image-dired--thumb-size= function falling back to 128; relief/margin to 2; thumbs-per-row to 3) before any thumbnail work. The crop target additionally falls back through =image-dired--thumb-size=, =dired-image-thumbnail--display-size=, and 128, and the refresh-time =/= comparison guards against nil.
- *Nil package options* -- =dired-image-thumbnail-minimum-file-size= (treated as check-disabled when nil) and =dired-image-thumbnail-window-ratio= (falls back to 0.4) are now guarded against nil values in =--image-p=, =--apply-layout=, and =--setup-display-buffer=.

** <2026-08-29 Sat> *2.2.4*

New features and keybinding changes.

*** New Features

- *Open image in its own buffer (f)* -- Added `dired-image-thumbnail-find-file` (bound to =f=), which visits the image at point with `find-file`, opening it in `image-mode` in a new window. This mirrors Dired's =f= (`dired-find-file`) and gives the full Emacs image-mode experience (zoom, save, convert), distinct from the split-screen display buffer used by navigation. Also available in the transient menu.

*** Changes

- *`?` now opens the transient menu* -- Previously bound to help (alongside =h=); =h= remains for help, =?= now invokes the transient menu (alongside =C-c .=).

** <2026-08-29 Sat> *2.2.3*

Fix for Emacs lock-file residue (`.#filename.jpg' symlinks) left in
image directories after navigating or marking/unmarking.

*** Bug Fixes

- *Lock-file residue on displayed images* -- Lock files (`.#filename.jpg' symlinks) were left in image directories after navigating or marking/unmarking. Root cause: the fast display path (=dired-image-thumbnail--display-image-fast=) reuses the =*image-dired-display-image*= buffer that was previously used by =image-dired-display-image= to visit a file. When the fast path calls =erase-buffer=, Emacs 30's lazy locking (=prepare_to_modify_buffer_1= in insdel.c) creates a lock on the previously-displayed image. The fast path now severs the file visit (=set-visited-file-name nil=) before modifying the buffer, and binds =create-lockfiles= to nil during the modification. Additionally, new defcustom =dired-image-thumbnail-suppress-display-lockfiles= (default =t=) provides =:around= advice on =image-dired-display-image= to suppress lock creation on the standard display path (for older Emacs versions that lock on visit).
- *Display buffer now killed on hide* -- =dired-image-thumbnail-hide-display= now kills the display buffer instead of burying it, releasing image data from memory and cleaning up any residual lock file.

** <2026-08-29 Sat> *2.2.2*

Code-review fixes: stale preview cache, cross-platform preview generation,
and buffer-initialization performance.

*** Bug Fixes

- *Stale preview cache for updated images* -- The preview cache key in =--make-preview= previously hashed only the file path and target width, so an image edited in place kept the same key and served an out-of-date preview indefinitely. The file's modification timestamp is now folded into the SHA1 payload, so modified images get fresh previews automatically.
- *Cross-platform preview generation* -- The =djpeg=/=cjpeg= fast path used =call-process-shell-command= with a =|= / =>= shell pipeline, which breaks on Windows =cmd.exe= and custom shell setups. It now chains two =call-process= calls through an intermediate temp file (cleaned up in =unwind-protect=), removing the shell dependency entirely.

*** Improvements

- *O(runs) buffer initialization* -- =--initialize-buffer= scanned the thumbnail buffer character-by-character with =forward-char= to find =associated-dired-buffer= and =original-file-name= properties. Both loops now jump between property-change boundaries with =next-single-property-change=, matching the optimization already used in =--prop-search= and =refresh=.
- *Consolidated =with-eval-after-load= blocks* -- The two back-to-back =with-eval-after-load 'image-dired= blocks at the end of the file (keymap setup / advice / hooks, and the =C-d= display-buffer keymap binding) are merged into a single block for clarity.
- *Transient auto-accept extracted to a named command* -- The inline =(lambda ...)= on the transient menu's =A= key is now the named command =dired-image-thumbnail-transient-toggle-auto-accept=, keeping the =transient-define-prefix= declaration clean and reusable.
- *Predicate ordered before first use* -- =dired-image-thumbnail--in-thumbnail-buffer-p= moved from the bottom of the transient file to a new =;;; Predicates= section above its first reference, preventing byte-compiler warnings during macro expansion.

** <2026-06-02 Tue> *2.2.1*

Bug fixes and marking/header-line performance.

*** Bug Fixes

- *Subdirectory images no longer lost on re-scan* -- The internal =--recursive= flag is now set when subdirectories have been inserted into the Dired buffer, so re-scanning (=g=/=r=, =re-scan=, =refresh-all= after a rename) keeps images from inserted subdirectories instead of silently dropping them.
- *=C-d= in the image display buffer now works at any quality* -- The fast scaled-display buffer previously used plain =special-mode=, so the =C-d= (delete-and-next) binding only worked at =full= quality. A dedicated =dired-image-thumbnail-display-mode= now carries the binding for every quality level.
- *Consistent trash behaviour on delete* -- =C-d= delete commands now honour =delete-by-moving-to-trash= like =D= and =x= did, instead of permanently deleting.

*** Improvements

- *O(N) marking* -- =M= (mark all), =t= (toggle all), and block region marking now make a single pass over the Dired buffer using a hash set, replacing the previous per-file =dired-goto-file= scans (O(N²)).
- *Cached marked count* -- The header-line marked count is cached and invalidated only when marks actually change, so navigating with =n=/=p= no longer rescans the Dired buffer on every keypress.
- *Faster thumbnail navigation* -- Finding the image at/near point and restoring point after a refresh now jump between text-property boundaries instead of scanning one character at a time.
- *Stable window layout rules* -- =display-buffer= rules are refreshed on each launch and de-duplicated, so they track the current =dired-image-thumbnail-window-layout= / =-window-ratio= values instead of going stale or stacking up.
- *Clean unload support* -- Added =dired-image-thumbnail-unload-function= so =unload-feature= removes all advice, hooks, and =display-buffer= rules the package installed.
- *Preview cache cleaned on exit* -- The temporary preview directory is now removed automatically via =kill-emacs-hook=.
- *Cleaner byte-compilation* -- Removed redundant sort/filter recomputation, added =subr-x= require and missing function declarations, replaced the obsolete =image-dired-thumb-height=, dropped a redundant dotfile check, and fixed docstring and free-variable warnings (both files now compile with zero warnings).

** <2026-05-14 Thu> *2.2.0*

Block Mark and Region Selection.

*** New Features

- *Block Mark (B)* -- Added `dired-image-thumbnail-mark-region` (bound to `B`) to mark all images in a selected region. Set the region with `C-SPC`, navigate to the other end, then press `B` to mark all images in that block at once. Much faster than marking each image individually.
- *Block Unmark* -- Added `dired-image-thumbnail-unmark-region` for symmetry (available via `M-x` or custom binding).

** <2026-05-04 Mon> *2.1.0*

Performance and Layout Refinement.

*** New Features

- *Targeted Dimension Invalidation* -- Added `dired-image-thumbnail-invalidate-files` to allow surgical clearing of the dimension cache. Significant speedup for batch operations like "crush" or "rotate" since the full cache no longer needs to be cleared.
- *Robust Window Placement* -- New custom `display-buffer` action `dired-image-thumbnail-display-at-direction`. Ensures that the image display buffer always reuses the correct window at the side (e.g., right), even if that window is currently visiting a text file or other buffer, preventing unwanted splits during navigation.

*** Improvements

- *Aggressive Lock Cleanup* -- Better integration with `transmute` package for cleaning up orphaned Emacs `.#` lock files after operations.
- *Dimension Query Optimization* -- Reduced redundant `identify` calls during batch refreshes.

** <2026-03-22 Sat> *2.0.0*

Major release: configurable window layouts, multi-level display quality with
external-tool preview generation, image file validation, and open-in-external-editor.

*** New Features

- *Configurable window layout* -- New =dired-image-thumbnail-window-layout=
  defcustom with presets: =left-right= (default), =right-left=, =top-bottom=,
  =bottom-top=, =thumb-only=, or =nil= (manual).  Replaces the old boolean
  =dired-image-thumbnail-manage-window-layout=.
- *Window size ratio* -- New =dired-image-thumbnail-window-ratio= (default
  0.4) controls how much of the frame the thumbnail buffer occupies.
- *Display quality levels (Q)* -- New =dired-image-thumbnail-display-quality=
  defcustom with five levels: =full=, =high=, =fast= (default), =faster=,
  =draft=.  Press =Q= in the thumbnail buffer to cycle through them.  Lower
  quality means faster navigation through large photo collections.
- *External-tool preview generation* -- For quality levels below =full=, preview
  images are generated using =djpeg=/=cjpeg= (for JPEGs, DCT-domain scaling)
  or =magick=/=convert= (for other formats).  This produces genuinely smaller
  files so Emacs decodes less data, giving a real speed improvement.
- *Image file validation* -- New =dired-image-thumbnail-minimum-file-size=
  (default 100 bytes) and =dired-image-thumbnail-validate-headers= (default
  =t=) defcustoms.  Files that are too small or lack valid image magic bytes
  (JPEG, PNG, GIF, BMP, TIFF, WEBP, ICO, HEIC/HEIF) are silently excluded
  from the thumbnail display.  Catches corrupt and truncated files.
- *Open in external editor (W)* -- Press =W= to open the image at point in an
  external application.  Configure =dired-image-thumbnail-external-editor= to
  a specific program (e.g. =gimp=, =krita=), or leave =nil= to use the system
  default (=xdg-open= / =open= / =start=).

*** Improvements

- *Quality shown in header line* -- The current display quality level is now
  shown in the header line alongside sort/filter status.
- *Header line updates on quality change* -- Pressing =Q= now immediately
  updates the header line to reflect the new quality level.
- *O(N) marked-file collection* -- Collecting marked files now uses a hash-set
  approach instead of per-file =dired-goto-file=, eliminating O(N²) overhead.
- *Robust async thumbnail sentinel* -- The identify-process sentinel now
  captures buffer references in a lexical closure and guards against killed
  buffers.
- *Directory switching fixed* -- Opening =dired-image-thumbnail= in a new
  directory now correctly clears stale state from the previous directory.
